# Mesta — проектный документ

*Название: **Mesta** · Домен: **mesta.city** (куплен, 22 €/год)*
*Версия 0.2*

---

## 1. Суть проекта

Гид по местам Валенсии, открытым и управляемым русскоязычными предпринимателями (Россия, Украина, Беларусь, Казахстан и др.), в формате красивой интерактивной карты + Telegram-канала + Telegram-бота.

**Что делает продукт:**
- показывает на карте проверенные места с карточками (фото, описание, соцсети, контакты, теги);
- рассказывает истории этих мест в Telegram-канале;
- через бота отдаёт ближайшие места по геолокации и собирает заявки/правки от аудитории.

**Стартовая вертикаль:** кофейни. Дальше — рестораны, барбершопы/бьюти, магазины (славянские продукты), автосервисы, детские кружки и школы, услуги (юристы, gestor, врачи, фотографы, репетиторы).

### Почему это может сработать
1. У тебя уже есть база мест — самый дорогой актив (холодный старт закрыт).
2. Ты живёшь в городе — можешь физически ходить, снимать, знакомиться с владельцами. Это то, что не масштабируется у конкурентов и то, ради чего люди подписываются.
3. Аудитория русскоязычных в Валенсии растёт и активно ищет «своих».
4. У бизнесов из этой ниши почти нет каналов таргетированной рекламы на свою аудиторию → есть готовность платить.

### Главные риски (честно)
| Риск | Суть | Что делать |
|---|---|---|
| Маленький рынок | Один город + узкая ниша = потолок дохода низкий | Сразу проектировать архитектуру мультигородской; город — параметр, а не хардкод |
| Медленная монетизация | Пока нет 2–5к аудитории, платить никто не будет | Первые 6 месяцев — контент и рост, не продажи |
| Устаревание данных | Места закрываются, меняют часы | Механика «сообщить о проблеме» + раз в квартал ревизия |
| Конкуренты | Существующие чаты/каналы «Русские в Валенсии» | Твоё отличие — курация и дизайн, а не полнота справочника |
| Позиционирование | Объединять RU/UA/BY в одну аудиторию — политически чувствительно для части людей | Формулировка должна быть про язык, а не про страну: «места, где говорят по-русски» / «русскоязычная Валенсия». Никакой политики в канале — это редакционное правило, а не мелочь |
| Права на фото | Чужие фото из Instagram — не твои | Снимать самому или брать письменное разрешение владельца |

## 2. Аудитория и сценарии

**Кто:**
- новоприбывшие (0–12 мес) — самая горячая аудитория, ищут всё сразу;
- давно живущие — ищут конкретное («где сделать брови», «где нормальный автосервис»);
- туристы из русскоязычной среды — короткая сессия, кофе/еда;
- сами владельцы бизнесов — будущие клиенты по монетизации.

**Ключевые сценарии (JTBD):**
1. «Я рядом, где выпить нормальный кофе и меня поймут» → бот, геолокация.
2. «Только переехал, покажите базу» → сайт, подборка «Старт в Валенсии».
3. «Ищу конкретную услугу на своём языке» → фильтр по категории.
4. «Хочу поддержать своих» → канал, истории.
5. «У меня бизнес, хочу попасть на карту» → форма / бот.

## 3. Что берём у The Scouts и что делаем иначе

**Берём:**
- карта как главный экран + лента карточек сбоку/снизу;
- система тегов вместо жёстких категорий (можно с ноутбуком, pet-friendly, веранда, завтраки);
- две формы: «Добавить заведение» и «Сообщить о проблеме» (структурированная — не работает / неактуальная инфа / добавить фото / указать часы);
- избранное (сердечки);
- связка с TG-каналом и Instagram;
- принципиальный отказ от рейтингов и «гонки звёзд» — это позиция, она хорошо продаётся аудитории.

**Делаем иначе:**
- **Telegram Mini App** — карта открывается прямо внутри Telegram. У The Scouts этого нет, а для нашей аудитории Telegram — родной интерфейс. Это главный дистрибуционный козырь.
- **Мультиязычность интерфейса (RU/ES/EN)**: местам важны и испанские клиенты, а тебе — SEO и возможность продавать рекламу шире.
- **Профиль места как самостоятельная SEO-страница** (`/valencia/coffee/nazvanie`) — бесплатный поисковый трафик по запросам «русская кофейня Валенсия».
- **Личный кабинет владельца места** (позже) — статистика просмотров карточки. Это фундамент платных тарифов.
- **Подборки/маршруты** — редакторский слой поверх базы («Кофе у моря», «Работать с ноутбуком», «Первая неделя в Валенсии»).

## 4. Функциональность

### 4.1 MVP (то, что делаем в первую очередь)

**Веб-карта:**
- MapLibre GL + кастомный стиль поверх OSM, кластеризация пинов;
- фильтр по тегам (в MVP — 6–10 тегов для кофеен);
- список карточек: превью-фото, название, адрес, расстояние (если разрешена геолокация);
- карточка места: галерея (до 4 фото), описание, теги, адрес, часы работы, телефон, Instagram, ссылка «построить маршрут» (deeplink в Google/Apple Maps);
- мобильный bottom-sheet вместо десктопного сайдбара;
- избранное в localStorage (без регистрации — регистрация убивает конверсию на старте);
- форма «Добавить место» и «Сообщить о проблеме» → в БД + уведомление тебе в Telegram.

**Telegram-бот:**
- `/start` → короткое приветствие + меню;
- кнопка «📍 Рядом со мной» → запрос геолокации → 5 ближайших мест с расстоянием и ссылкой на карточку;
- «☕ Категории» → инлайн-список;
- «➕ Добавить место» → диалог из 4–5 шагов → запись в БД + уведомление админу;
- «✍️ Написать нам» → свободный текст → тебе в личку;
- ссылка на канал и на Mini App.

**Telegram-канал:**
- 2–3 поста в неделю: новое место / история владельца / подборка;
- закреплённый пост со ссылкой на карту.

**Админка:**
- на старте — **Adminer или pgAdmin** (лёгкий веб-клиент для Postgres, разворачивается на Railway отдельным сервисом в один клик) для прямого просмотра/правки таблиц. Своя `/admin`-страница нужна только под очередь модерации заявок — остальное делаешь через SQL-клиент. Не трать недели на полноценную админку, пока мест меньше 200.
- отдельная страница `/admin` — только очередь модерации заявок (approve/reject в один клик).

### 4.2 Версия 1.1 (первые 2–3 месяца после запуска)
- Telegram Mini App (та же вебка, обёрнутая в TMA SDK, авторизация через Telegram initData);
- избранное синхронизируется с TG-аккаунтом;
- новые категории (рестораны, магазины, услуги);
- подборки/коллекции;
- поиск по названию;
- испанская и английская локализации;
- «Открылось на этой неделе» — блок новинок;
- PWA-манифест (добавить на главный экран).

### 4.3 Версия 2 (при подтверждённом росте)
- личный кабинет владельца места: редактировать карточку, видеть статистику, публиковать акции;
- промо-размещения (см. монетизацию);
- отзывы/оценки — **осознанно откладываем**: модерация UGC — это работа, а конкурентное преимущество у нас в курации;
- второй город (Аликанте / Барселона / Малага) как копия конфигурации;
- рассылка-дайджест в боте (раз в неделю, opt-in).

### 4.4 Дополнительные идеи (в бэклог, не для MVP)
- **Промокоды партнёров.** «Скажи, что ты с карты — скидка 10%». Даёт бизнесу измеримый ROI → главный аргумент при продаже размещения.
- **Digital-паспорт места**: QR-наклейка на дверь заведения «Мы на карте». Бесплатный офлайн-канал привлечения.
- **«Ищу»-раздел** — заявки аудитории («ищу русскоговорящего стоматолога»). Отличный источник контента и понимания спроса.
- **Карта событий** — концерты, стендапы, разговорные клубы. Событийный контент даёт возвращаемость.
- **Экспорт в Google My Maps** для тех, кто не пользуется Telegram.
- **Виджет-эмбед** карты для сайтов партнёров (релокейт-агентства, языковые школы) — бесплатный трафик.
- **Раздел «Первые 30 дней в Валенсии»** — NIE, empadronamiento, банк, симка. Это самый частый поисковый запрос новоприбывших и мощнейший SEO-магнит; связывает справочник с картой.

## 5. Технический стек

Приоритет: минимальная стоимость, минимум инфраструктуры, максимум скорости.

| Слой | Выбор | Почему |
|---|---|---|
| Фронт | **Next.js 15 (App Router) + TypeScript + Tailwind** | SSR/SSG для SEO-страниц мест, один код для сайта и Mini App |
| Карта | **MapLibre GL JS** | Open-source, векторные тайлы, полный контроль над стилем, WebGL |
| Тайлы | **Protomaps (PMTiles)** — см. раздел 6 | Один статический файл, near-zero cost |
| БД | **Postgres + PostGIS на Railway** (образ `postgis/postgis`) | Уже оплаченный тариф, гео-запросы «ближайшие» из коробки, приватная сеть с ботом и сайтом |
| Хранение фото | **Cloudflare R2** | Нулевой egress; на Railway нет аналога Supabase Storage «из коробки» — грузим напрямую в R2 через S3-совместимый API |
| Хостинг | **Railway** (уже есть тариф) | Один проект: сайт + БД + бот, приватная сеть между сервисами |
| БД (уточнение) | **Postgres на Railway** через образ `postgis/postgis` (Docker-сервис), не дефолтный Railway Postgres template — в нём PostGIS не предустановлен | Гео-запросы «ближайшие» из коробки |
| Бот | **grammY (TypeScript)**, long polling, always-on процесс на Railway | На Railway не нужен serverless webhook — процесс живёт постоянно, меньше мороки с подписью запросов |
| Домен | **mesta.city**, зарегистрирован на Cloudflare Registrar, 22 €/год | DNS на Cloudflare, CNAME → Railway |
| Фото + PMTiles | **Cloudflare R2** (нулевой egress), не Railway volume | Объектное хранилище + CDN дешевле и быстрее раздаёт статику, чем диск, привязанный к сервису |
| Аналитика | Plausible / Umami self-hosted | Без cookie-баннера (важно для GDPR) |
| Формы/уведомления | Telegram Bot API в свой админ-чат | Бесплатно, мгновенно |

> Если веб-опыта мало, альтернатива на старте: **Astro + статический JSON** вместо БД на Railway. Сайт собирается из файлов, деплой на Cloudflare Pages, ноль бэкенда. Но тогда бот не сможет писать заявки в общую БД — придётся ограничиться уведомлениями. Мой совет: сразу Postgres на Railway, кривая обучения окупается за неделю, тем более тариф уже оплачен.

### 5.1 Инфраструктура: Railway + Cloudflare (финальное решение)

Разделение по типу нагрузки:

| Компонент | Где живёт | Почему |
|---|---|---|
| Postgres + PostGIS, сайт (Next.js), бот | **Railway** (один проект, общий приватный network) | Уже оплаченный тариф, zero-DevOps, бот стучится в БД напрямую без публичного API |
| Домен `mesta.city`, DNS | **Cloudflare** | Регистратор без наценки, DNS + проксирование бесплатно |
| Фото мест, файл `.pmtiles` | **Cloudflare R2** | Объектное хранилище с CDN и нулевым egress — Railway volume для этого не подходит: он диск, а не CDN, PMTiles требует быстрых HTTP range-запросов по всему миру |

**Настройка PostGIS на Railway** (кратко):
1. В Railway — New Service → Docker Image → `postgis/postgis:16-3.4` (не дефолтный Postgres-темплейт, в нём расширения нет).
2. Прокинуть переменные окружения как в обычном Postgres-сервисе Railway (`POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`).
3. Подключиться и выполнить `CREATE EXTENSION IF NOT EXISTS postgis;`.
4. Остальные сервисы (сайт, бот) обращаются к БД через приватный Railway-домен (`*.railway.internal`) — без выхода в интернет, быстрее и безопаснее.

**Подключение домена:**
1. Домен куплен на Cloudflare Registrar → DNS уже на Cloudflare автоматически.
2. В Railway: Settings → Domains → Add Custom Domain → `mesta.city`.
3. В Cloudflare DNS: добавить CNAME, который выдаст Railway, включить проксирование (оранжевое облако) — получаешь бесплатный SSL и CDN-кеш заодно.
4. Для R2 с фото/pmtiles — поддомен `assets.mesta.city`, тоже через Cloudflare, отдельная CNAME-запись на publicly-accessible R2 bucket.

## 6. Как сделать красивую карту поверх бесплатного OSM

Это твой главный вопрос, разбираю подробно.

### Почему «уродливо» получается по умолчанию
Стандартный путь — Leaflet + растровые тайлы `tile.openstreetmap.org`. Это картинки, нарисованные чужим стилем: их нельзя перекрасить, нельзя убрать лишние POI, они пиксельные на ретине, и по usage policy их нельзя грузить на трафике продакшн-проекта. Отсюда ощущение «сырого OSM».

### Правильный путь: векторные тайлы + свой style.json
MapLibre GL рендерит не картинки, а данные — геометрию дорог, зданий, воды. Внешний вид полностью описывается JSON-файлом стиля: цвета, толщины, шрифты, какие слои показывать на каком зуме. Ты можешь сделать монохромную карту, тёплую бежевую, тёмную — что угодно, не трогая данные.

**Откуда брать векторные тайлы (три варианта):**

**A. Protomaps hosted API** — самый быстрый старт. API отдаёт MVT-векторные тайлы через Style JSON, TileJSON или ZXY-URL, требуется API-ключ с CORS-ограничениями. Подключается одной строкой в конфиг MapLibre.

**B. Self-hosted PMTiles — рекомендую для нас.** PMTiles — это формат, позволяющий держать все векторные тайлы в одном статическом файле на обычном объектном хранилище; клиент забирает нужные куски через HTTP range-запросы. Ты вырезаешь экстракт только Comunitat Valenciana (десятки–сотни МБ вместо 100+ ГБ мирового файла), кладёшь на Cloudflare R2 (нулевой egress) — и стоимость карты становится фактически нулевой навсегда, без ключей и лимитов. Подключение: библиотека `pmtiles` регистрирует протокол в MapLibre, и источник указывается как `pmtiles://https://.../valencia.pmtiles`.

**C. MapTiler / Stadia Maps** — free-тиры есть, но с лимитами запросов и брендингом. Как запасной вариант.

**Стиль:** не пиши style.json с нуля. Пакет `@protomaps/basemaps` генерирует готовые слои для MapLibre в нескольких цветовых «флейворах», а через maps.protomaps.com можно выгрузить статический Style JSON. Берёшь `light` или `grayscale` как основу и правишь под свою палитру. Для визуального редактирования — **Maputnik** (веб-редактор стилей, экспортирует тот же JSON). Шрифты (glyphs) и спрайты подключаются отдельными URL — их можно хостить у себя, скачав из basemaps-assets.

### Что конкретно делает карту «дизайнерской»
1. **Приглушить фон.** Базовая карта должна быть почти монохромной (беж/серый/тёплый белый). Все цветовые акценты — только на твоих пинах.
2. **Убрать чужие POI.** Удали из стиля слои с чужими магазинами и иконками. На карте должны быть только твои места — это и есть главный визуальный эффект.
3. **Меньше подписей.** Оставь районы и крупные улицы, убери мелочь до высоких зумов.
4. **Свои пины.** SVG-маркеры в стиле бренда (чашка для кофеен, вилка для ресторанов), разные для обычных и промо-мест. Не дефолтные капли.
5. **Кластеризация** (`cluster: true` в GeoJSON-источнике) — без неё 100+ пинов превращаются в кашу.
6. **Шрифт.** Кастомный фонтстек через font-maker сразу выдаёт «сделано дизайнером».
7. **Анимации.** `flyTo` при выборе карточки, плавное раскрытие bottom-sheet, скелетоны при загрузке фото.
8. **UI поверх карты, а не рядом.** Плавающая строка поиска, чипсы-фильтры сверху, карточки снизу — как в Airbnb/Google Maps.
9. **Тёмная тема** — переключение флейвора стиля, дёшево и выглядит дорого.

### Обязательно
Атрибуция OpenStreetMap (ODbL) должна быть видна на карте. Это не опция.

## 7. Модель данных (набросок)

```sql
cities         (
  id, slug, name_ru, name_es, center_lat, center_lng, default_zoom,
  theme_bg, theme_surface, theme_primary, theme_text, theme_text_secondary,
  theme_dark_bg, theme_dark_surface, theme_dark_primary, theme_dark_text
)
categories     (id, slug, name_ru, name_es, name_en, icon, sort_order)
tags           (id, slug, name_ru, name_es, name_en, category_id nullable)

places (
  id, city_id, category_id,
  slug,                       -- для SEO-урла
  name, name_original,        -- «Кафе Дом» / «Casa Café»
  description_ru, description_es, description_en,
  address, location geography(Point,4326),   -- PostGIS + GiST-индекс
  phone, whatsapp, website, instagram, telegram, google_maps_url,
  opening_hours jsonb,        -- по дням + перерывы, как в референсе
  photos jsonb,               -- массив путей в Storage
  owner_note,                 -- «Владелец из Киева, открылись в 2023»
  languages text[],           -- ['ru','es','en','uk']
  status,                     -- draft | published | closed | hidden
  is_featured bool, featured_until timestamptz,   -- под монетизацию
  created_at, updated_at, verified_at
)

place_tags     (place_id, tag_id)
submissions    (id, type, payload jsonb, source, tg_user_id, status, created_at)
place_views    (place_id, day, count)          -- статистика для владельцев
```

Запрос «ближайшие» для бота:
```sql
SELECT id, name, ST_Distance(location, ST_MakePoint($lng,$lat)::geography) AS dist
FROM places WHERE status='published' AND city_id=$city
ORDER BY location <-> ST_MakePoint($lng,$lat)::geography LIMIT 5;
```

### 7.1 Тема оформления по городам

Палитра — часть данных, не хардкод в компонентах. Это ключевое архитектурное решение для мультигорода: добавление нового города = новая строка в БД + новый флейвор карты в Maputnik, без изменений в коде компонентов.

**Механизм:**
- Цвета города хранятся в таблице `cities` (поля выше) в виде hex-строк.
- На уровне layout конкретного города они прокидываются в CSS-переменные:
  ```css
  :root[data-city="valencia"] {
    --color-bg: #FAF3E9;
    --color-surface: #FFFDF9;
    --color-primary: #E8622C;
    --color-text: #2B2420;
    --color-text-secondary: #8A7A6D;
  }
  :root[data-city="valencia"][data-theme="dark"] {
    --color-bg: #1C1712;
    --color-surface: #2A231D;
    --color-primary: #F0855A;
    --color-text: #F5EDE1;
  }
  ```
- Компоненты (кнопки, чипсы, bottom-sheet, свои пины на карте) стилизуются только через `var(--color-*)`, никогда напрямую цветом.
- Тёмная тема — не механическая инверсия. Тёплый акцент на холодном чёрном «вибрирует» и режет глаза; тёмный фон должен быть тёплым (коричневатым), а акцент — светлее и чуть желтее исходного.

**Валенсия — оранжевый/терракотовый.** Ассоциация с апельсинами (символ региона) и терракотовой плиткой — тематически точное попадание, не просто «красиво».

| Роль | Светлая тема | Тёмная тема |
|---|---|---|
| Background | `#FAF3E9` (тёплый бежевый, не чистый белый — иначе резче контраст с оранжевым) | `#1C1712` (тёплый тёмно-коричневый, не сине-чёрный) |
| Surface (карточки) | `#FFFDF9` | `#2A231D` |
| Primary (акцент) | `#E8622C` | `#F0855A` (светлее и желтее для баланса на тёмном) |
| Text primary | `#2B2420` | `#F5EDE1` |
| Text secondary | `#8A7A6D` | — |

**Порту — сине-белый азулежу (референс для проверки масштабируемости системы, не для реализации сейчас).**

| Роль | Светлая тема | Тёмная тема |
|---|---|---|
| Background | `#F2F0EA` | `#0F1E2E` |
| Primary | `#2C5F8A` (кобальт) | светлее/ярче того же синего |

**Стиль карты (MapLibre) тоже завязан на тему:** в Maputnik делаешь два флейвора на город (light/dark) через `@protomaps/basemaps`, переключение — той же CSS-переменной/атрибутом `data-theme`, без перезагрузки страницы (source остаётся, меняется только `style`).

## 8. Монетизация — лестница

Правило: **не продавать раньше, чем аудитория канала перевалит за 1500–2000 и на карте будет 80+ мест.** Ранняя реклама убивает доверие, а доверие — единственный актив проекта.

**Этап 1 (мес. 0–4): ноль монетизации.** Растим базу и канал. Собираем цифры (просмотры карточек, переходы в Instagram мест) — это будущий прайс-лист.

**Этап 2 (мес. 4–8): бартер и первые деньги.**
- рекламный пост в канале — 30–60 € (цена = f(подписчики));
- «место недели» — закреп + карточка в топе на 7 дней;
- бартер: обзор в обмен на промокод для аудитории. Формирует кейсы.

**Этап 3 (мес. 8+): подписка для бизнесов.**
- **Free** — базовая карточка (все места, всегда бесплатно; иначе карта перестанет быть полной и потеряет ценность);
- **Pro ~15–25 €/мес** — приоритет в выдаче, расширенная галерея, кнопка «акция», статистика просмотров, бейдж «проверено»;
- **Partner ~50 €/мес** — Pro + пост в канале раз в квартал + место в подборках.

**Этап 4: расширение.**
- новый город = новая рекламная площадка (модель уже отлажена);
- партнёрка с релокейт-агентствами и языковыми школами (CPA);
- платный «Гид новоприбывшего» (PDF/мини-курс) — но осторожно, это другой бизнес.

**Реалистичный ориентир:** один город при 3–5к аудитории — 300–800 €/мес. Это pet-project с приятным доходом, не работа. Настоящие деньги — только в мультигороде.

**Юридически:** принимать деньги в Испании — значит выставлять факторы и платить IVA. Разберись с alta de autónomo или разовыми счетами до первой продажи (я не консультант — сходи к gestor'у).

## 12. Персональный план: бэкенд-опыт, 10–20 ч/нед, сайт первым

### 12.1 Решение по стеку

**Next.js 15 (App Router) + TypeScript + Tailwind + shadcn/ui + MapLibre GL.**

Почему именно так при отсутствии фронтового опыта:

1. **shadcn/ui закрывает твою главную боль** — «не понимаю, как сделать красиво». Это не библиотека, а набор готовых компонентов (кнопки, sheet, dialog, badge, скелетоны), которые копируются в твой проект уже с выверенной типографикой и отступами. Тебе не надо принимать дизайн-решения — только собирать из блоков.
2. **Ты всё равно будешь писать JS.** MapLibre — это JS-библиотека, обойти её нельзя. Вопрос только в том, писать ли ещё и второй язык на бэкенде. Один язык на весь проект (фронт + API + бот) экономит десятки часов.
3. **Railway = почти нулевой DevOps.** Один проект держит сайт, Postgres+PostGIS и бота с общим приватным network — не нужно поднимать nginx или отдельно настраивать сертификаты, Railway и Cloudflare берут это на себя.
4. **Mini App потом бесплатно.** TMA — это та же вебка внутри Telegram. Если фронт на Next, добавление TMA — день работы, а не переписывание.

**Честная альтернатива, если React вызовет отторжение:** FastAPI/Django + Jinja-шаблоны + vanilla MapLibre без сборщика. Для этого проекта работоспособно — контент по сути статический, интерактив один. Но состояние экрана карты (выбранный пин ↔ подсвеченная карточка ↔ активные фильтры ↔ открытый bottom-sheet) на голом JS довольно быстро превращается в спагетти. Я бы взял этот путь, только если после первой недели React реально не пойдёт.

### 12.2 Минимальный React, который тебе нужен

Не учи экосистему целиком. Для этого проекта достаточно шести вещей:

1. Компонент = функция, возвращающая JSX. Всё.
2. `useState` — локальное состояние.
3. `useEffect` — сайд-эффекты (инициализация карты, подписка на события).
4. `useRef` — держать инстанс MapLibre между рендерами. **Ключевой момент:** карта живёт вне React, в ref; React ей не управляет.
5. Пропсы вниз, колбэки вверх.
6. Server Components vs Client Components: по умолчанию всё серверное; файл с `'use client'` наверху — интерактивный. Карта и фильтры — клиентские, страницы мест — серверные.

**Что игнорировать:** Redux, React Query (на старте не нужен), Context, кастомные хуки, тесты, Storybook, анимационные библиотеки.

### 12.3 Структура проекта

```
app/
  page.tsx                    -- главная: карта (Server → рендерит <MapView/>)
  [city]/[category]/[slug]/page.tsx  -- SEO-страница места (SSG)
  admin/page.tsx              -- очередь модерации

components/
```

Обрати внимание: `/api/nearby` один на сайт и на бота. Не дублируй логику.

### 12.4 План на 4 недели (10–20 ч/нед)

**Неделя 1 — данные и карта на экране**

### 12.6 Где ты потеряешь время (предупреждаю заранее)

- **Стиль карты.** Maputnik затягивает: можно неделю крутить оттенки серого. Ограничь себя одним вечером, потом вернёшься.
- **Фото.** Главный визуальный фактор доверия. Плохие фото убьют любой дизайн. Лучше 20 мест с твоими собственными снимками, чем 60 со скриншотами из Instagram.
- **Часы работы.** Структура `jsonb` с перерывами и выходными — на удивление муторная задача и постоянно устаревающие данные. В MVP можно ограничиться строкой и ссылкой на Google Maps.
